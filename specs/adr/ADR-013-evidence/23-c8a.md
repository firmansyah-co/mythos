- **C8a** (the VM's part of task configuration: a run suspended and resumed, the scheduler core,
  2026-11-22). Added, in `crates/mythos-logic-vm`: `Run` (a `Copy` value with private fields, no
  references; `Run::begin(program, now, budget)`, `Run::resume(program, memory, stack, calls,
  piece) -> Result<Piece, Fault>`, `Run::now`, `Run::instructions`, `Run::ended`) and
  `enum Piece { Ended(ScanReport), Suspended }`. `scan()` keeps its signature: it is
  `Run::begin` and one piece of `u32::MAX`. The new module `sched` (core only): `LOWEST_PRIORITY`
  (31), `Kind` (`Cycle { min_cycle }`, `Cyclic { interval, phase }`, `Startup`, `Event`),
  `Counters` (`runs`, `overruns`, `preemptions`, `last_run`, `longest_run`, `last_end`; a value
  not measured yet is `None`, not 0), `Task` (`new`, `kind`, `priority`, `counters`, `is_ready`,
  `in_progress`), `Next` (`Idle`, `Begin(i)`, `Resume(i)`) and the functions `start`, `trigger`,
  `next`, `ended`, `wake`. The caller owns the slice of tasks and passes the program and the
  slices on every `resume`; `resume` checks their sizes again each time. Decided: a piece of 0 is
  a piece of 1; there is no new `Fault` variant (resuming an ended run executes nothing and
  answers the same end or the same fault); a cycle task ranks as priority 32 and its minimum
  cycle time runs from the start of one run to the start of the next; run times are measured from
  begin to end, preemption included; an event triggered while ready is not queued, and one
  triggered while in progress is ready again after the run ends. The crate keeps `#![no_std]`,
  `#![forbid(unsafe_code)]` and an empty `[dependencies]`. No route was added, so no MCP tool.

  **Found in an independent review, each fixed with a named test:** (1) `sched` decided overruns
  only inside `next()`, so a cyclic run that ended after its next due time, with no `next()`
  call in between, got the missed run made late and no overrun counted: the outcome depended on
  where the pieces fell. Now `ended()` counts every due time strictly before the end as an
  overrun and moves `due` past it; a due time exactly at the end makes a run
  (`an_overrun_is_counted_the_same_whether_or_not_the_host_asked_during_the_run`, failed before
  the fix). (2) `Run::resume` panicked with an index out of bounds in `Stack::pop` when a run
  suspended in one program was resumed with another whose stack is shallower. Now a saved stack
  or call depth above the program's returns `Fault::WrongSizes`, checked once per piece
  (`a_run_resumed_with_a_program_of_a_shallower_stack_faults_and_does_not_panic`, panicked
  before the fix). (3) A cycle task ready again was stamped ready since `began + min_cycle`,
  which can lie before its own end, so it could pass an equal cycle task ready longer. Now
  `due = max(began + min_cycle, end)`
  (`a_cycle_task_ready_again_at_its_end_does_not_pass_one_ready_since_before`, failed before the
  fix). (4) `sched::release` used unchecked `i64` arithmetic and panicked in debug, wrapped in
  release, for extreme times. Now the distance is `abs_diff` in `u64`, the count and the due
  time saturate, and the overrun count saturates at `u32::MAX`
  (`times_at_the_ends_of_the_clock_saturate_and_do_not_overflow`, panicked before the fix).
  (5) No test pinned three decided rules; the behaviour was already correct, so these are
  coverage, not red-tested: `an_event_triggered_twice_before_it_runs_makes_one_run_and_once_during_its_run_one_more`
  and `several_startup_tasks_run_in_priority_order_before_everything_and_a_cyclic_task_counts_its_overruns_meanwhile`.
  The reviewer also compared every local of the old scan loop with `Run` (all are saved on
  suspension) and found `scan()` unchanged in behaviour.
