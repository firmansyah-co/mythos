# ADR-013 evidence: D1

Part of [ADR-013](../ADR-013-logic-compiler-and-vm.md), section 5.

- **D1** (data blocks in the compiler, the first slice of ADR-014: library sources, VAR_EXTERNAL,
  the members a program writes, the layout hash, 2026-11-22). Nothing uses the new API yet. The
  logic module still compiles each program from its own source, and no runtime hands a data
  block over. Those are later slices of ADR-014. The bytecode format and the VM do not change.

  **Added, in the compiler** (`crates/mythos-logic-compiler/src/lib.rs`): `Sources` gains
  `library: &[(&str, &str)]` (the name and text of Structured Text sources that hold TYPE
  blocks, functions and function block types, no PROGRAM) and `data: &[DataBlock]`; it keeps
  `Default`, `Clone` and `Copy`. `DataBlock { name, ty }` is a re-export of the type in
  `mythos_logic_st`. `Compiled` gains `data: Vec<DataUse>`, empty for a program that declares no
  data block. `DataUse` (`name`, `ty` serialised as `type`, `layout`, `offset`, `size`,
  `constant`, `members`) and `DataMember` (`name`, `ty`, `offset`, `size`, `written`) are
  `Serialize` and `Deserialize`. `DataLayout` (`name`, `ty`, `layout`, `size`, `members`) is a
  block as laid out with no program. `check_project(&Sources)` checks the library sources and the
  data block declarations and lays the blocks out; it does not look at `st` or `tc6`. In a
  `DataUse` and a `DataLayout`, `name` and `ty` are the project's spelling. `DataMember.ty` is
  the IR type name (`INT`, `ARRAY [0..3] OF INT`, `STRING[8]`, a structure's declared name).
  `compile`, `compile_in`, `lower` and `lower_sources` keep their signatures.

  **Added, in the IR** (`mythos-logic-ir`): `Section::External` (serialised `external`),
  `Var.constant` (skipped when false), `Store { var, member }` and `Unit::stores(pou)`, which
  names every place a body writes: an assignment, the FOR control variable, a function block
  call instance and each call output. Its match lists every statement kind with no wildcard, so
  a new kind does not compile until it says what it stores. A store whose first selector is
  member m sets member m. A store with no path, an index first, or a member index out of range
  sets every member. `IR_VERSION` goes from 6 to 7.

  **Added, in Structured Text** (`mythos-logic-st`): `VarDecl.constant`; the module `project`
  (`DataBlock`, `Project { library, data }`, `FIRST_LINE`, `SOURCE_LINES`, `MAX_SOURCES`,
  `first_line`, `source_of`, `add_library`, `used_only`, `declared`, `name_sources`);
  `lower_project`, `lower_tree_in`, `check_project`, `PROJECT_PROGRAM` (`__PROJECT`),
  `check::check_in`. `VAR_EXTERNAL [CONSTANT]` is read for a PROGRAM. `parser::no_retention` is
  now `pub`, with no change of behaviour in ST. **In the backend** (`mythos-logic-backend-vm`):
  `ExternalLayout`, `Output.externals`, `layout_hash` and `data_layouts` (the plan stage of
  `emit`, with no code emitted). **In the graphic front-ends** (`mythos-logic-graphic`):
  `lower_project_with_probes`, and `read.rs` reads `<externalVars>` and
  `<externalVars constant="true">` as `VAR_EXTERNAL` for every POU kind instead of refusing
  them. `globalVars` keeps its old message, `globalVars (VAR_EXTERNAL, VAR_GLOBAL) is not
  supported yet`.

  **How library sources work.** Library source k has its lines from 2^30 + k * 2^20, after the
  program's source and the standard library and before TC6 at 2^31. A diagnostic on such a line
  is mapped back to the source name through the existing `Diagnostic.source` mechanism, with the
  line made relative to the source. More than 1024 library sources, or one of more than 2^20
  lines, is one whole-program diagnostic. The library is checked on its own first (the library
  plus the synthetic program `__PROJECT`, which declares each data block in `VAR_EXTERNAL`), so
  a library never sees a name only a program declares. If that check fails, its diagnostics and
  the parse diagnostics of the program's sources are returned and nothing more is checked. If it
  is clean, the tree of the program and the library is checked whole, then pruned
  (`project::used_only` keeps library types and POUs by name, transitively, from the program's
  items) and checked again; the second check gives the Unit, so what the program does not use
  adds nothing to what is compiled. A library item is recognised by its span line in
  [2^30, 2^31). `compile_sources` calls `check_project` when the project is not empty, and
  `check_project` lays out every library type with `data_layouts`, used or not. With library
  sources present the program's own ST diagnostics are named with the ST source name.

  **The layout hash.** The canonical text, documented on `Layouts::canonical` in the backend, is
  `D1;<size>;` and then `STRUCT(NAME:<type>@<offset>+<size>;...)`, with elementary names,
  `STRING[n]`, `ARRAY[lo..hi,...]OF(<elem>)` and no structure type names. The hash is FNV-1a 64
  over its bytes, 16 lowercase hex digits. `Small { a : INT; s : STRING[4] }` gives
  `d41e45e02f9128e0`; an independent Python FNV-1a over the canonical text gives the same.

  **Departures from the contract and decisions.**
  - `plugins/logic/src/lib.rs` is edited, two lines (`..Default::default()` in its two `Sources`
    literals), although the task said not to edit `plugins/`. The new fields make a literal
    without them a compile error, and the contract requires `cargo check --workspace
    --all-targets` to pass. The plugin's behaviour does not change. Seven existing compiler test
    files get one `..Default::default()` line each, for the same reason; no assertion is
    changed.
  - FOR over a data block member cannot be tested end to end. The parser refuses any FOR control
    variable that is a member or an element (`a FOR variable that is a member or an element
    (name it alone) is not supported yet`), a whole block cannot be one, and TC6 has no FOR. The
    IR unit test covers `Stmt::For` in `Unit::stores`; a test checks that the ST form is refused
    with the existing message.
  - Library sources also work for TC6 programs, which is wider than "stage 1 is ST programs":
    the compiler routes to `lower_project_with_probes` when `tc6` is not empty and the project is
    not empty.
  - `no_retention` in the ST parser went from private to `pub`, so the TC6 reader gives RETAIN
    on `externalVars` ST's message and not a copy. Without constant, RETAIN or NON_RETAIN is
    refused with `<RETAIN|NON_RETAIN> is not allowed on VAR_EXTERNAL: ...`; with constant the
    existing `CONSTANT does not combine with RETAIN or NON_RETAIN` message applies.
  - The SFC test pins no step count. A first literal (2 after two scans) was wrong for this
    engine's activation timing, and the SFC timing was not traced. The test compares with the
    same chart over variables of its own; the one bound kept is `steps >= 2` after the 7 scans.
  - The reader passes `externalVars` through for every POU kind and name, initial values
    included; the program-only rule, block existence, type match and the no-initial-value rule
    are the shared ST checker's (`declare_external`), so TC6 and ST give one answer. With no
    library and no data, a TC6 `externalVars` now gets `there is no data block <n> in the
    project`, where it got `not supported yet`; no existing test asserted the old message.
  - The contract gives no wording for the refusals of a block's name; the messages are in
    `each_refusal_of_a_data_block_has_its_message`. The same name in different sources is
    `<name> is declared twice: in <A> and in <B>`, each side being the library source's name or
    `the program`. Project-level diagnostics of a data block are whole-program (line 0, no
    source); a program-level refusal points at the declaration, the type or the initial value.
  - `written` is never forced to false for CONSTANT; the checker refuses the stores, so a store
    that got through would show as written. `VAR_EXTERNAL CONSTANT` uses the checker's existing
    readonly mechanism in `place_root`, and every write path (assignment, FOR, `=>`) goes
    through `assign_to(writing)`.
  - Review fix 2 changed one assertion this slice wrote in
    `each_refusal_of_a_data_block_has_its_message`: a block typed by a structure of the program
    now gives `data block 'B': there is no type Local`, which is what `check_project` says, and
    the test asserts the equality. The checker branch that gives the older message stays for
    direct callers of `check::check_in`.
  - The name-collision check of a block counts only names declared in a library source. In
    `check_project` the layout of each block is measured on its own: the backend's
    `Program::EachVariable` mode leaves out the entry program's size and the summed memory, and
    every structure, function block and function is still measured alone. `emit` is unchanged.
    In that mode the `offset` of each `ExternalLayout` is the synthetic program's and
    `check_project` does not use it.

  **What the two reviews found.** The review of the written members found two defects. F1
  (medium, LIVE): a library source could name a type or POU only the program declares, so the
  same block got a different layout in each program (for the repro, layout `d1896a5285069b47`,
  size 4, in one program and `06d6a524f072533d`, size 18, in the other) and `check_project`
  refused a library every program compiled against. It is fixed by checking the library alone
  first. F2 (low, LIVE): a block named like a program was refused only when that program was
  compiled, and the `is a <type>` message depended on the program. It is fixed as described
  above. The review of compatibility found three LATENT defects. F3: a library type too large
  for the bytecode format was not reported when no program used it; fixed by `data_layouts`. F4:
  `check_project` summed all blocks against the whole-program size limit; fixed by
  `Program::EachVariable`. F5: with more than 1024 library sources every use of a library name
  got a follow-on diagnostic; fixed by setting `tree.lost` as the over-long-source branch does,
  with the duplicate whole-program diagnostic removed in `lower_tree_in`. Each fix has a test
  above that failed without the fix and passes with it.
