# ADR-013 evidence: C8b

Part of [ADR-013](../ADR-013-logic-compiler-and-vm.md), section 5.

- **C8b** (several programs in several tasks in one runtime: the module protocol, the VM runner
  and the core, 2026-11-22). Added, in the protocol (`crates/mythos-module/src/protocol.rs`):
  `TaskConfig` (`name`, `kind`, `priority` 0 to 31 and required, `watchdog_ms` skipped when
  absent, `programs`; unknown fields refused), `TaskKind` (`Cycle { min_cycle_ms }`, `Cyclic {
  interval_ms, phase_ms }`, `Startup {}`, `Event { tag }`, tagged by `type`, unknown fields
  refused in each), `TaskKind::name`, `TaskSupport` (`of(profile)` reads
  `profile["tasks"].kinds`), `ProgramVersion`, `TaskState` (the figures of one task;
  `last_run_us`, `longest_run_us` and `run_age_us` are `Option`), `implied_task`,
  `LOWEST_TASK_PRIORITY` (31) and `check_tasks`, the check the core and the module share.
  `RuntimeState` gains `tasks` and `programs`, both skipped when empty. `PROTOCOL_VERSION` stays
  1.  Added, in the module (`plugins/runtime-vm`, version 0.4.0 to 0.5.0): one scheduler thread
  for every runtime, the implied single cyclic task included, in the new `src/tasks.rs`. It uses
  `mythos_logic_vm::sched` and `Run`, runs a piece of `PIECE` (10,000) instructions with no lock
  held, and keeps each program's working memory on the thread. Each program has a process image,
  copied from its memory when the last program of its task ends a run. Exchanges read samples and
  outputs from the images, so they see the last completed run. A task's inputs are latched for all
  its programs when the task begins. Forces are held at the latch and at the end of a run. A fault
  in any program, a watchdog fault, and every change of mode increment a generation, and a run
  that ends under another generation writes nothing. The manifest profile declares `"tasks":
  {"kinds": ["cycle","cyclic","startup","event"]}`. A startup task runs at every change to RUN,
  warm or cold, and at a process restart; at an online change (started with carried values) the
  startup tasks are given to `sched` as event tasks that are never triggered. An event task runs
  on a rising edge from a GOOD FALSE to a GOOD TRUE, read from the inputs of the current exchange;
  the first exchange, a missing tag and a not-GOOD sample make no edge. Each task has its own
  watchdog. With several programs a variable is named `<program>.<path>` in Watch, Force, Unforce,
  Variables, Carried and Retained, the program matched without regard to case.  Added, in the core
  (`crates/mythos-core/src/runtimes.rs`, `mcp.rs`): `RuntimeInstance` has `program` as an
  `Option`, `programs` and `tasks`; `all_programs`, `effective_tasks`, `runs_as_today` and
  `program_key` read them. `RuntimeStatus` gains `programs` and `tasks`, taken only from the
  module's last `RuntimeState`, and `interval_ms` becomes `Option<u64>`. `validate` and the driver
  run the per-instance checks, `check_tasks` and the uniqueness of output and published tags
  across the programs of a runtime. The driver keeps the module's `TaskSupport` and refuses, in
  `describe_config` and in `start`, a runtime that does not run as today when the module does not
  declare `profile.tasks`, and a task kind the module does not list. The exchange period follows
  the tasks: today's rule when the runtime runs as today, else 20 ms with an event task, else the
  smallest cyclic interval clamped, else 200 ms. An online change needs the same set of program
  names. The MCP body schema of `save_runtimes_config` has `program`, `programs` and `tasks`.  **A
  project of today is unaffected.** One program in no task keeps the implied task (named after the
  program, cyclic at the program's interval, priority 31), which is the only task the module runs

  `a_save_for_an_older_runtime_module_is_refused_and_says_why` (400 with the section 2 text,
  nothing saved).  **Departures from the contract.** (1) `TaskKind::Startup` is the struct variant
  `Startup {}`, not a unit variant: serde accepts `deny_unknown_fields` on the internally tagged
  enum, but a unit variant ignores unknown fields (`{"type":"startup","cold":true}` was accepted
  and a test caught it). The wire form is unchanged. (2) The watchdog measures a cyclic or cycle
  task from when its next run is due (the first start plus phase plus k times interval at or after
  it was fed or its last end; for a cycle task the later of its end and began plus `min_cycle`),
  not from the later of being fed and its last end. The contract's rule would fault a healthy task
  whose `watchdog_ms` is below its interval, or whose phase is longer than its limit, and put a
  working plant's outputs to safe. Guarded by
  `a_watchdog_shorter_than_its_interval_faults_no_task_waiting_for_its_time`. (3) A startup task
  owes its run from the first exchange after RUN, not from the mode change, because no run can
  begin before the first inputs. (4) Public items the contract does not list: `implied_task`,
  `LOWEST_TASK_PRIORITY`, `TaskKind::name`. (5) `check_tasks` takes the merged program list, so it
  cannot see `program` and `programs` together or the event tag's type; the module checks both in
  `plan()` and the core checks both/neither in `RuntimeDriver::parse`, with the contract's words.
  (6) The contract says the cyclic program's first run sees `boot = TRUE`; programs share no
  memory, so this is not observable. The order is proved instead by the startup run that outlasts
  a priority-0 cyclic task's interval with zero preemptions. (7) The exchange period uses today's
  rule only when `runs_as_today()` holds, not for every runtime of one program; one program in a
  task of another interval or kind uses the task rule. (8) `program_key` returns a sorted list of
  names, not a string joined by `,`, so the sets {a,b ; c} and {a ; b,c} differ; the message joins
  them with `,`, so for one program it reads as before. (9) In RUN, when a runtime has tasks
  written out, an output the module's reply leaves out (its program's task has not run) is written
  its safe value once; the contract's section 4 had the module report no output for it and the
  core write nothing. A runtime with no tasks written out is left as before. (10) The refusal of
  one cyclic task by an older module names `interval_ms`, `phase_ms` and `watchdog_ms` when they
  are why it does not run as today, which section 2 does not say. (11) A runtime of one program
  given in `programs` is refused by a module that does not declare tasks, in its own words,
  because such a module reads only `program`. (12) `ProcessDriver::open` refuses a restarted
  process that is another build (a different version or profile) of the discovered module, which
  the contract does not mention. (13) The run, overrun and preemption counters of `sched` are
  `u64`, not `u32` (change to `crates/mythos-logic-vm/src/sched.rs`). (14) Two stage 2 tests are
  in `runtime_api.rs`, not `runtime_vm.rs`, because only `IoManager` fills how a load started and
  the save is the PUT route. (15) The MCP schema's program `interval_ms` has minimum 0 and a task
  `kind` is a `oneOf` with a required-field list per type. (16) `validate` runs every per-instance
  check before the cross-instance uniqueness checks, so a configuration with two different
  mistakes can report a different one first than before; a configuration with one mistake reports
  today's message. (17) `plugins/runtime-vm` has `mythos-logic-compiler` as a dev-dependency. (18)
  The ADR sentence about catching up is corrected, as contract decision 7 says; the contract
